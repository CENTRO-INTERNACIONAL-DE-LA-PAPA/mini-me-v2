# Roadmap

Mini-Me is built one [OpenSpec](../openspec/) change at a time, in this order. Each change is
proposed, reviewed, implemented, verified and archived before the next one starts.

| # | Change | Scope | Status |
|---|---|---|---|
| 1 | Event protocol and project storage | Event envelope and delivery, Mini-Me Data and Project folders, Conversations, Assets, `#` references, reactions, minimal UI with a temporary echo responder | Done |
| 2 | Sidecar runtime | Bundled Python (pinned with `uv`) started and supervised by the Rust core, JSON lines over stdin/stdout with a version handshake, the Trait interface, the echo responder moved into Python as the first Trait. No API keys or costs. | Done |
| 3 | Releases and auto-update | GitHub Actions builds the Windows per-user installer on each version tag and creates a draft GitHub Release with signed update files; installed apps see it once it is published. Installed apps download updates automatically with progress shown, then ask you to restart (or install when closed). No macOS or Linux release builds: macOS is built locally. Installers are not code-signed: CIP IT allowlists the bundled `python.exe` by path, and the app is named Mini-Me. | Done |
| 4 | First real Trait | AI provider keys in the OS keychain, a Settings screen with provider and model selection, one AI-backed Trait (for example *Summarize*), Mini-Me definitions with the shared Trait library and one-Step Workflows, `@`-mentions of Mini-Mes, optional Mini-Me reactions to your messages | Done |
| 5 | Routing | Typesafe Jev picks a Mini-Me when none is mentioned; below a confidence threshold, you choose | Done |
| 6 | Conversation context | Adapters ask the core for a Conversation's earlier messages when they need them (a `core.request` method, as for Assets), a convention for replies from other Mini-Mes in the same Conversation, a size budget per call, how files referenced in earlier messages are carried over, and Jev deciding whether a message needs previous context at all | Done |
| 7 | Asta integration and Traits | [allenai/asta-plugins](https://github.com/allenai/asta-plugins) pinned in the sidecar, signing in with your Ai2 account, *Find Papers* (Paper Finder) with Researcher and *Theorize* (Theorizer) with Theorist | Done |
| 8 | First Interactive Components | Interactive Components shown below a reply's text: hand-coded, versioned kinds that built-in Traits list and use; Paper sources for *Find Papers* and Theories for *Theorize*; Mini-Mes saving generated files as Assets | Done |
| 9 | Built-in Traits | *Scout*, *Refute*, *Plan*, *Wonder* and *Experiment*, each with its own Mini-Me (Explorer, Skeptic, Planner, Inquirer and Experimenter); the Traits that later changes build join the library as placeholders | Done |
| 10 | Data Traits: inspect and prepare | *Profile Data*, *Validate Data*, *Clean Data* and *Join Data* as tools built into the sidecar, with no code written by the AI model, each with its own Mini-Me (Profiler, Validator, Curator and Linker); a sortable table Interactive Component (selecting and referencing parts of it moved to #14) | Done |
| 11 | Workflow engine | Multi-Step Workflows with control Steps (approval, condition, loop, parallel), stored as data and run as LangGraph graphs in the sidecar, so the link carries a Mini-Me run instead of single Trait calls. A reply shows its Workflow's progress; a run paused at an approval is saved through the core in `project.sqlite`, so it survives closing the app. Investigator, a new built-in Mini-Me, uses all four control Steps | Done |
| 12 | Charts | *Plot* and its Mini-Me, Plotter: the AI model chooses histograms, bar, line, scatter and box charts or correlation heatmaps, and pandas computes their values. A chart Interactive Component drawn with Observable Plot, with hover values, series that can be hidden, alternative chart types and a colour for every series; tables drop TanStack Table | Done |
| 13 | Project Overview | The view of everything a Project has produced: a summary written by the AI model on request, an output the user features from a reply, and the latest tables, charts, papers, theories and files Mini-Mes made | Done |
| 14 | Table and chart references | Referencing a whole table or chart Interactive Component in a message with `$`, for example `$field-trial-cleaned`, from a reference button on the component or the composer's `$` list; the core resolves it so Traits work on exactly that component. Each kind of reference has its own sign: `@` for a Mini-Me, `#` for a file and `$` for a table or chart | Done |
| 15 | Mini-Me and Trait editors | A Library listing Mini-Mes (filterable by group) and Traits, opened from the sidebar, with editors to create, edit, duplicate and delete them, stored app-wide in Mini-Me Data by the Rust core and offered to routing. Built-in Mini-Mes and Traits can only be duplicated. A user-made Trait is prompt-based: it sets its instructions and the tools its model may use, and cannot be deleted while a Mini-Me uses it. A user-made Mini-Me picks its avatar, colour and group, and its Workflow is an ordered list of Trait Steps; a duplicate with control Steps keeps them, locked until #16 | Done |
| 16 | Visual Workflow editor | The Mini-Me editor's Workflow, Traits and Appearance tabs. The Workflow tab draws a Mini-Me's Workflow on a canvas (React Flow), laid out automatically from its Steps; Trait and control Steps are added from a toolbar and moved by dragging them onto connectors, and an inspector edits the selected Step, including an "Ask before running" approval. Built-in Workflows are shown read-only | Done |
| 17 | Real data for placeholders | A `user-profile.json` with the user's name, set in Settings and shown in Home's greeting, the sidebar and Files; Home's "Waiting on you" lists replies paused at an approval across Projects and opens them; the Jobs panel lists the replies running in any Conversation; a Conversation Outline panel of the Mini-Mes, files and tables and charts it uses replaces the To-do panel; the sample data is removed | Done |
| 18 | Home | Every Mini-Me, built-in and user-made, shown behind Home's content as avatars with physics (Matter.js): they drop in, pile up and can be grabbed, thrown and clicked for their name; the Home sidebar lists the 5 most recent Conversations across Projects | Done |
| 19 | Dev channel | "Mini-Me Dev" as a separate app next to the production one: its own identifier, name and dev icon, its own Mini-Me Data folder, settings and keychain entries, so development never touches real Projects; `npm run tauri:dev` runs as Mini-Me Dev, which never checks for updates; Settings is regrouped into General, Models & keys, Accounts and About, with the app's version and a Developer mode that shows the [DEBUG] options and the web inspector | Done |
| 20 | Documents | Quarto (`.qmd`) documents in a Project: a `write_document` tool for Assist, Summarize and user-made Traits; a Report option in a Conversation to draft from it, start blank or open one from Files; a full-width document view with its Quarto source, formatting buttons, an outline and a preview of its pages; PDF export through Typst | Done |
| 21 | Comments and suggestions | Comment threads anchored to passages of a document's source and stored in the Project, in a Comments sheet beside the document; @-mentioning a Mini-Me in a comment runs its Workflow on the thread and the passage, and it answers in the thread with suggested edits, shown in its colour in the source until you accept, retry or discard each one | Done |
| 22 | Editing documents from a Conversation | An `edit_document` tool for Assist, Summarize and user-made Traits, so a Mini-Me asked in a Conversation sends suggested edits to a document, which you accept or reject in the document view | Done |
| 23 | Feature flags | Experimental features shipped switched off, each with its own key written in the code: entering the key in Settings → Developer turns the feature on for that installation, until it is turned off again; every flag starts on in Mini-Me Dev; the UI and Traits ask the core which flags are on | Done |
| 24 | Test cleanup | Tests check behaviour, not versions or data: version, snapshot and dependency tests go, the sidecar's model-call tests go as `openspec/config.yaml` requires, duplicates become table tests, and the `#[ignore]`d real-sidecar tests go. Projects made before comment threads, paused replies or Interactive Components are no longer supported, so the workarounds for them go with their tests | Next |
| 25 | Comment cleanup | Comments shortened to what the code cannot say, and wrong or misplaced ones fixed, per the Comments rules in `CLAUDE.md` | |
| 26 | Shared helpers and dead code | Code written several times by hand becomes one helper, long functions are split, rows read into structs instead of tuples, and unused code is removed | |
| 27 | File splits and merges | Files that hold several concerns are split (`runs.rs`, `ipc.rs`, `store.rs`, `SettingsView.tsx`, ...), and small files that share one concern and are imported together are merged | |
| 28 | One source for shared names | The tool and AI provider names that the Rust core and the sidecar both list come from one JSON file that both read, like `library/builtin.json` | |

Later: code execution (Python and R) with OS-level sandboxing, collaboration through a relay
server, Microsoft SSO, Dataverse upload, Asta's AutoDiscovery with confirmation before any
action with an extra cost.
